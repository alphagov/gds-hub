## What was built

- **Terraform (Part 1)** in `infrastructure/terraform/`: network, RDS PostgreSQL 18 with a managed master secret, ECR, log groups, IAM, WAF, the Express Mode service (created only when `create_service` is true) and the schema and data migration task definitions. Tasks run on ARM64 through the service module's `cpu_architecture` variable (default `ARM64`).
- **Database settings:** `src/config.ts` builds `databaseUrl` from `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER` and `DATABASE_PASSWORD`, URL-encoded, with `sslmode=verify-full`.
- **Image:** the Dockerfile downloads the RDS CA bundle with a pinned SHA-256, sets `NODE_EXTRA_CA_CERTS` and copies `drizzle/`.
- **`TRUST_PROXY_HOPS`:** an optional whole number from 0 (default 0). `createApp` applies it with `app.set("trust proxy", n)`. Development passes `2`, for CloudFront and the load balancer. Documented in the README configuration table.
- **CloudFront (added 2026-11-27)** in `infrastructure/terraform/modules/cdn/`: a distribution on the default `*.cloudfront.net` domain, with a `CLOUDFRONT`-scope web ACL (IP allow-list and rate limit, created in `us-east-1` through an `aws.us_east_1` provider alias). CloudFront sends a secret `X-Origin-Verify` header, generated by `random_password`, and the regional web ACL in `modules/edge/` now allows only requests carrying it. Pages aren't cached; `/assets/*` is.

## Decisions

- **A hop count, not `true`.** With `true`, Express trusts every `X-Forwarded-For` entry and a client can pick its own `req.ip`. A number trusts only that many proxies from the app side. The default is 0, so local runs and tests trust no forwarded header.
- **`trustProxyHops` is a required field of `Config`**, so `testConfig` in `test/unit/helpers.ts` gained it.
- **Nothing in `src` reads `req.ip`, `req.ips` or an `X-Forwarded-*` header yet.** The request logger and the audit actor don't use the client address, so no existing behaviour changes. When something does (rate limiting, audit entries with an address), it gets the right address from `req.ip`.
- **The IP allow-list is on CloudFront, not the load balancer.** Behind CloudFront the regional web ACL sees only CloudFront's addresses, so it checks the origin header instead, and the rate limit moved too (it would otherwise count all viewers behind one edge address).
- **No page caching yet.** Each page carries a per-request CSP nonce, and caching it would reuse the nonce; `/edit/*`, preview and `/search` must never be cached. Caching read pages is Phase 12.
- **IPv6 is off on the distribution,** because the allow-list is IPv4 only and IPv6 viewers would always be blocked.
- **The origin secret comes from `hashicorp/random`,** so nobody types or stores it. It is in state only. Rotating it causes 403s for a few minutes while CloudFront rolls out; the no-downtime approach is in the backlog.
- **No runbook file yet.** The manual steps are below. Part 2 adds `docs/deployment.md`, with the deploy workflow.

## Needs the developer

Cannot run in the sandbox (no Docker, Terraform or AWS CLI):

- `docker build --platform linux/arm64 --build-arg APP_VERSION=<sha> .`, including the pinned CA bundle download.
- `terraform fmt -check`, `terraform validate` and `terraform plan` in `bootstrap/` and `environments/development/`, then both applies.
- The first deploy, in this order (read values with `terraform output -raw <name>` into shell variables and never print them):
  1. Build the image for `linux/arm64` with `APP_VERSION` set to the short commit hash, and push it to ECR. ECR tags are immutable, so each build needs a new tag. Note the image digest.
  2. Register a new revision of the schema migration task definition with the digest, then run it with `run-task` on the public subnets with `assignPublicIp` enabled. The exit code must be 0 and the log must show the migrations applied.
  3. Check the RDS secret has `username` and `password` keys, PostgreSQL 18 is offered in the region, and secret rotation is off.
  4. Set `create_service = true` and `app_image = "<ECR URL>@sha256:<digest>"` in `terraform.tfvars`, then plan and apply. Expect the Express service and the WAF association to be added.
  5. Check `/health` through the service URL from an allowed address (since CloudFront, through `cloudfront_domain`: the service URL now refuses direct requests), that no security group Express created allows `0.0.0.0/0` inbound on port 3000, and that the WAF is associated. The app logs nothing on a successful database connection, so verified TLS is shown by the schema migration logging `migrations applied` and a database-backed page loading, with no `self-signed certificate in certificate chain` or `Hostname/IP does not match certificate's altnames` errors in the logs.
  6. If the image build fails the CA bundle checksum, AWS has rotated the bundle: download the new one, check its certificates and update the hash in the `Dockerfile`.
- CloudFront (the first deploy above was confirmed working by the developer on 2026-11-27):
  1. In `environments/development/`, run `terraform init` to install `hashicorp/random` (done), and commit the updated `.terraform.lock.hcl`.
  2. Run `terraform fmt -check -recursive`, `terraform validate` and `terraform plan`. Expect the new `cdn` module (random password, IP set and web ACL in `us-east-1`, distribution), the regional web ACL updated in place, its IP set destroyed, and a new service deployment for `TRUST_PROXY_HOPS = 2`.
  3. Apply in two steps. Terraform doesn't update the regional web ACL before destroying the IP set it references, so a single apply fails with `WAFAssociatedItemException`. First run `terraform apply -target=module.edge.aws_wafv2_web_acl.this`, which creates the `cdn` module, waits for the distribution and then updates the web ACL. Then run `terraform apply` to destroy the old IP set and roll out `TRUST_PROXY_HOPS`. The Express URL keeps working until the CloudFront URL is ready. Afterwards, set `alb_arn` in `terraform.tfvars` to the value of `terraform output -raw load_balancer_arn`. Otherwise, whenever anything upstream changes, Terraform defers the load balancer lookup and plans to replace the WAF association, which leaves the load balancer without a web ACL for a moment.
  4. Check: the CloudFront URL (`terraform output -raw cloudfront_domain`) serves pages from an allowed IP and gives 403 from others; the Express URL gives 403 even from an allowed IP; `/assets/*` responses show `x-cache` hits or revalidations; and a 502 from CloudFront would mean the Express certificate doesn't match its endpoint name.
